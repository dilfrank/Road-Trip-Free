# 需求基线与对话决策

## 需求演进
|阶段|用户要求|现行处理|
|1.0评审|文字、按钮、装饰线过多；流程重复|保留极简原则，去掉无意义标记和重复步骤|
|2.0视觉|渐变、黄金比例、苹果式简洁、留白|渐变用于出行条件；比例是设计方向，不应牺牲输入可用性|
|理论与Prompt|旅游幸福：定义、度假效应、期待/现场/回忆、机制、个体与社区|转化为需求分类及方案比较维度，不作为幸福预测模型|
|Emotionapps|查询并与新版Prompt比较、写入项目|既有研究依据见框架文档；不能宣称识别无意识情绪或自动诊断|
|中国资料|阅读并接入 E盘自驾资料|本机检索及来源页码；旧资料不是当前开放、价格、路况事实|
|五模块|Intent / Places / Planner / Validator / Explainer|作为工程职责保留，不要求用户逐步操作五次|
|输入交互|计划与箭头功能不清楚，增添逻辑归类|明确出行条件展开与整理提交；主题可选，不强制填完整问卷|
|最终主流程|填好后一次输出三套方案并用表格比较|现行最高优先级交互基线；替代先确认再选景点的旧流程|
|交付|同步GitHub、截图和初学者演示|教程必须说明填什么、点哪里、会得到什么；不能把截图轮播称为连续录屏|

## 可追溯需求
- R01 一次提交得到三套不同方案；条件缺失时定位缺项。
- R02 输入支持感受、期待、顾虑、同行关系、意义、回忆、社区七类，保留完整原话。
- R03 推断必须有原话证据，并标为待确认；一次提交不等于确认所有推断。
- R04 比较期待/现场/回忆、放松/投入/关系/意义，以及驾驶、费用、顾虑与取舍。
- R05 景点必须来自可追溯真实候选；保留来源编号、页码、待核实状态。
- R06 完整行程覆盖去程、停留、休息与返程；未知不能写成已满足。
- R07 UI简洁、明确、留白；必要提示不能因“去除小字”而消失。
- R08 原始资料全文和密钥不进入公开仓库。
- R09 新手可照例填写并完成全流程；截图、操作教程与当前界面一致。

## 已替代和未授权事项
旧版 California MVP、Step1/2/3 展示、重复确认和先手动选择景点不是当前首页的目标。旧代码保留在 legacy 便于追溯。
“2.0”是产品版本，不代表所有模块验收完成。国内全量目的地、实时天气/预约/住宿、公开生产服务、幸福评分均不得自行宣称已实现。
