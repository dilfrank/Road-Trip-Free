# 开发待办与验收

|优先级|任务|完成标准|
|P0|核对本地与远端基线|记录远端提交、本地分支、所有差异；无文件丢失|
|P0|真实模型/地图接通|密钥仅本机保存；各完成一次成功调用和一次失败场景；配置存在不算接通|
|P0|三方案约束可靠性|对否定、预算、驾驶上限测试；不可行或未知明确标记，不强凑三套可行方案|
|P1|入口坐标及行程编排|核实出发地址、入口/停车点、跨日住宿、停留及返程；不以城市中心冒充景区入口|
|P1|候选覆盖扩展|每条具备来源、页码、事实状态；新地区出发不默认为四川可行|
|P1|解释可追溯|每项匹配理由关联用户原话和核验结果；无依据项标未知|
|P1|教程重新验收|初学者按示例独立提交；桌面三列可比较，手机横滑明确；截图日期与示例说明一致|
|P2|工程模块拆分|行为不变、契约测试通过、无前端密钥引用|
|P2|公开部署准备|身份认证、持久化额度控制、监控与隐私说明完成后才开放服务|

## 回归清单
1. 空想法/缺日期/非法天数显示明确提示。
2. 提交时禁重复请求；修改输入后旧结果不能覆盖新输入。
3. 明确偏好与推断不混用；不喜欢爬山不能被当作喜欢爬山。
4. 三套列出不同候选和完整往返；不是三套相同模板换名字。
5. 服务断开、数据过期、模糊地址、驾驶超限均不显示“核验通过”。
6. 来源文件变化时索引报告不一致，不冒充最新资料。
7. 不在Git中提交密钥、原始攻略或全文索引。

验证命令：npm test；npm run build。浏览器验收另行记录；mock/fixture测试通过不等于服务真实联调通过。

每项验证记录：日期、提交SHA、环境、输入、预期、实际、截图/日志、未解决问题。
