# 自驾自由 2.0：从理解人到可核对的行程

## 产品定位
面向 South Bay 出发、2–5 天 California 自驾的人，先理解这次旅行想获得的体验，再由用户选择景点，最后提供能逐项核对的行程。延续 1.0 的情绪价值优先，不把热门景点数量作为成功指标。

2026-11-06 更新：采用旅游幸福框架组织目标、时间过程、体验机制与个体/社区影响；借鉴 Emotionapps 改善内部情绪理解。两者的分工与证据边界见 [应用规范](EMOTIONAPPS_FRAMEWORK.md)，执行提示词见 [Prompt 套件](V2_PROMPTS.md)。分析链条不是已验证的因果关系。

意图模块下一步应区分当前感受、期望体验、担忧、个人重要性、混合感受和未知信息；保留原话证据、用户确认状态及记录/体验阶段。此项目前为规范，尚未替换关键词规则。接入前先落实结构验证与确认流程，不增加前台理论问卷。

## 1.0 审计
现有 Next.js + React + TypeScript 项目包含 12 条路线、关键词情绪识别、景点推荐、加权排序、逐日行程和复制摘要。自然语言目前使用关键词规则，不是大模型理解；驾驶时间和季节信息是静态数据。

主要缺口：页面承担过多职责；表单修改会使展示结果与条件不一致；景点默认勾选并不代表用户意愿；路线匹配使用模板全部景点而非最终日程；压缩行程可能丢失中间地点和返程连接；没有真实道路计算。

## 功能参考与验收
当前“参考”指本项目 1.0，未假定用户指定其他竞品。

1. 保留“想法 → 景点 → 路线”；修改需求后旧路线不可见。
2. 景点不预选，少于两个无法生成；修改选择后旧路线失效。
3. “包含景点”必须能在实际逐日 stops 中找到；遗漏必须明确呈现。
4. 天数短于模板日数时排除模板，不能直接切断线路；无候选时给调整提示。
5. 总驾驶时间来自实际日程求和；超时逐日展示，不能宣称完全符合。
6. 不将静态季节提醒描述为实时道路或天气核验。
